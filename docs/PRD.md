## 1. 一句话产品定义

**给上海电机学院在读学生（当前即用户本人）的一款"零广告、教务系统直连导入、以当天课程为核心"的 Android 课表工具，让"今天上什么课、几点、在哪"在开机一瞥与一次启动内被解决。**

核心价值主张（差异化一句话）：**竞品把课表当流量入口，我们只把它当工具——不塞广告、不逼注册、不搞社交，导入一次，整个学期不操心。**

## 2. 目标用户与用户画像

### 2.1 主要用户画像（唯一真实用户）

| 维度 | 内容 |
|------|------|
| 身份 | 上海电机学院 自动化专业 2026 级 大一新生 |
| 校区 | 临港校区 |
| 技术水平 | 能自己登录教务系统、实测抓取课表原始数据；非专业开发，但愿意折腾 |
| 设备 | Android 手机（原生 Kotlin + Jetpack Compose 技术栈） |
| 当前课业强度 | 该学期约 **14 门课 + 2 门备注课**；周一至周三排满，周四下午起与周五很空，周六日无课 |
| 现解决方案 | 手动扒教务系统网页 / 靠记忆 / 纸质或截图 |
| 现状痛点 | 教务系统是 PC 网页，手机上看体验差；同一门课不同周会换教室甚至换教师，靠记忆必错；无提醒，早八靠自律 |

### 2.2 用户真实诉求（问题而非方案）

- 用户嘴上说："我要做一个课表 App。"
- 用户真正要解决的问题：**"我每天出门前，要能 3 秒内确认今天要上什么课、几点、在哪个教室；换学期时不用重来；早八不迟到。"**
- 由此推导：产品**不是**一个"功能齐全的课程管理平台"，而是**一个"今日行程确认器 + 学期可靠性兜底"**。凡是与"确认今天在哪上课"无关的功能，一律不做（见第 7 节 Out-of-Scope）。

### 2.3 次要用户画像

暂不存在。本产品明确不服务"找同课同学""分享课表""班级协作"等多人场景。若未来用户想把 App 给室友用，属于 Out-of-Scope 的"何时再考虑"触发条件（见 7.x）。

## 3. 核心使用场景

### 场景 A：开学导入（每学期一次，但决定全局成败）

大一上第 1 周，用户在宿舍打开 App，输入学号 + 统一身份认证密码（`authserver.sdju.edu.cn` 的 SSO），App 从 `https://jwgl.sdju.edu.cn/home` 拉取本学期课表并解析入库。**成功标准：一次导入即得到与教务系统一致的全部课程，包括单双周、多教师换教室、线上课。**

### 场景 B：每天出门前确认当天课程（每日高频）

07:30 起床，点亮屏幕看桌面小组件，或在负一屏 / 通知栏确认："今天 08:10-09:40 高等数学，E教116；10:10-11:40 大学英语，B105……" 若上一节即将开始，收到提醒"还有 15 分钟，大学物理 B(1)，B105"。

### 场景 C：上课途中临时改主意看整周（中频）

周三中午，想知道"这周五到底有没有课、能不能回家"，切到周视图网格，一眼看到周五全天空白，周六日空白。

### 场景 D：开学换学期（每学期切换，关键场景）

大一下开学前，App 提示切换学期。用户选择"2026-2027 学年第 2 学期"，重新用 SSO 导入新学期课表。**成功标准：切换学期后，"当天课程"主界面必须自动刷新为新学期数据，不允许残留上一学期的旧课，也不允许要求用户手动清库重建。**

### 场景 E：教务系统改版 / 换域名（异常兜底，P1）

某天学校教务系统改版，自动导入失效。用户用手动编辑课程功能，至少把当天 / 本周的课补进去，让 App 不至于当天完全作废，等适配完成后再恢复自动导入。

### 场景 F：早八不迟到（贯穿）

前一晚 22:00 与当天 07:30 各一次提醒，含课程名 + 时间 + 教室，且**不被国产 ROM 的后台清理杀掉**。

## 4. 关键数据形状（PRD 必须能容纳）

来自用户实测的真实课表（2026-2027 学年第 1 学期，学期起始日 **2026-09-14**，临港校区）。产品数据模型必须容纳以下形状，否则导入即崩：

### 4.1 课程字段

课程名称、课程代码（如 `053017P1-15`）、总学时、周次范围（如 `2-16 双周`、`3-15 单周`、`9-16`）、节次（如 `1-2 节`）、具体时间（如 `08:10-09:40`）、校区（临港校区）、教室（如 `E教116`）、教师（如 `李彬彬`）。

### 4.2 四个必须处理的"反直觉"数据形状

1. **同一门课不同周换教室 / 换教师**（不能按"课程表行"简单存一行）：
   - 「大学物理B(1)」：第 2 周在 `E教305`；第 3-16 周在 `B105`。
   - 「自动化专业导论与职业生涯规划」：第 2 周 `D教203` 陈国初；3-4 周 `B203` 蒋璐峥；5、8 周 `B203` 陈国初；6-7 周 `B203` 于妍。
2. **每周实验室不同**：
   - 「大学物理实验B(1)」：9-11 周 `204(实验室2)`；12 周 `202(实验室1)`；13 周 `309(实验室11)`；14 周 `305(实验室7)`；15-16 周 `308(实验室10)`。
3. **单双周规则**：`2-16 双周`、`3-15 单周`、`9-16`（每周）。
4. **无实体教室 / 无固定时间地点的备注课**：
   - 纯线上：尔雅通识课《航空与航天》，5-16 周，无实体教室。
   - 无固定时间地点：「军事技能」。

> **数据建模结论（给架构师的输入信号，非技术决策）**：存储粒度应为"**课程实例（CourseOccurrence）= 课程名 + 课程代码 + 周次规则集（weekRule）+ 时间 + 教室 + 教师**"，同一课程名可对应多个实例。"当天课程"与"周视图"渲染前，需先按"给定日期 -&gt; 命中哪些实例"做一次规则求值。纯线上 / 无时间地点的课不能塞进网格，应有独立分区（如"线上 / 不排座"）。

### 5.3 差评提炼：市场空白与真实痛点（按严重度排序）

1. **广告污染核心功能（第一痛点，也是最不可原谅的）**
   - WakeUp：App Store 1.7/5，"更新完打开全是广告""甚至开屏广告还自带巨大震动效果，直接自己就跳转了"；老用户永久会员被单方面剥夺、逼二次付费。
   - 超级课程表："只要手机有一点晃动，哪怕是你转个身或者在走路都会打开广告""手机平躺着放在桌上就又给我自己跳 tb 去了"；广告甚至挡在切换星期的位置上，"一点就转去其他应用"。
   - 课程格子：少量广告 + 无关课表的功能。
   - **空白**：一个"绝对无广告、无会员、无付费"的课表工具，在差评语境里被反复呼唤（"有没有没广告的课表软件，之前没广告多好"）。
2. **教务导入失败 / 识别错误 -&gt; 直接导致旷课，信任崩塌（第二痛点）**
   - WakeUp："课表完全识别错误……有的排的连续四五天都没课""开学了发现它课表给我乱排"。
   - 课程格子：早年把"一周两节的课只显示一节，直接导致我旷课"；教师姓名出现错别字。
   - 有用户反馈"教务系统好像加密了，怎么登都登不上"。部分手机（如荣耀）导不进，被迫换 App。
   - **空白**：导入结果的**准确性 / 可核对性**比"支持 3000 所高校"更重要。用户需要"导入后能一眼核对、导入失败有兜底"。
3. **提醒失效 -&gt; 迟到（高频抱怨，直击"早八"场景）**
   - "害我好几次迟到了"；"部分机型存在后台被杀导致提醒失效"；需手动把 App 设为"不受限制"。
   - **空白**：针对国产 ROM 的提醒可靠性设计（前台服务 / 精确闹钟 / 引导白名单）是刚需，但竞品普遍没做透。
4. **换学期 / 学期管理体验差**
   - 部分 App 切换学期后数据错乱、要重建；学期起始日期识别错（WakeUp 会识别错开学第一周）。
   - **空白**：一键切换学期后，"当天课程"自动且正确地刷新。
5. **功能臃肿、社交 / 娱乐喧宾夺主**
   - 超级课程表：校花校草榜、传小纸条被吐槽"用就用一个课程表，你要手机号码注册干什么"。
   - 少数派测评结论："他们对中国大多数大学生群体和课程模式了解得还不够""大多数同学是不需要课程表软件的社交功能的"。
   - **空白**：把范围砍到"导入 + 看 + 提醒"，是差异化。
6. **隐私与强制注册**
   - "就用一个课程表，你要手机号码注册干什么？还要定位干什么？"；共享课表默认公开专业 / 年级 / 课程，无法隐藏字段。
   - **空白**：本地优先、不注册、不采集。
7. **界面杂乱 / 动画卡顿 / 小组件不可靠**
   - "布局混乱""周视图周末空白造成空间不合理""小组件在 iOS 上有时空着不加载"。
   - **空白**：现代、顺滑的过渡动画 + 信息清晰的小组件，是被明确要求却常被忽视的点。

### 5.4 替代方案为何不够用

- **教务系统网页 / i 电机小程序**：数据 100% 准确，但要逐层点进"学生个人课表"，PC 网页手机端体验差，无提醒、无小组件、无今日聚合、每次都要联网登录。
- **系统日历手动建日程**：可靠但要手动逐条录入 14 门课 × 单双周规则，一节课换教室还要建多条，开学工作量巨大且易错；且没有"课表网格"语义（早八 / 第几节无法直观呈现）。

### 5.5 我们的差异化定位

| 对手的软肋 | 我们的做法 |
|-----------|-----------|
| 广告 / 会员 / 摇一摇跳转 | **零广告、零会员、零付费**，这是产品存在的第一理由 |
| 导入识别错 -&gt; 旷课 | 导入后提供**核对视图**（哪些课、哪些周、哪些教室），导入失败给**手动兜底**（P1）|
| 提醒被后台杀 -&gt; 迟到 | 提醒可靠性作为**硬指标**（见第 9 节成功指标）|
| 换学期数据错乱 | "换学期自动刷新当天课程"作为**验收标准**（Given/When/Then）|
| 功能臃肿、要注册 | **本地优先、不注册、不社交**，只做"导入 + 今日 + 周视图 + 小组件 + 提醒" |
| 界面杂乱、无动画 | 极简数据密集风 + 全局过渡动画 |

## 6. 功能清单（RICE 排序）

### 6.1 说明

- **范围澄清**：用户已全选的功能范围**全部纳入第一版（MVP）**，不删减。下表的 **P0 / P1 / P2 仅表示"实现顺序与时间分配优先级"，不代表"做 / 不做"**。真正的"不做"见第 7 节 Out-of-Scope。
- **RICE 定义**（自用项目场景下）：
  - Reach：每周被该功能触达 / 使用到的场景频次，归一化 1-10。
  - Impact：对"确认今天在哪上课"这一核心目标的贡献，0.25 / 0.5 / 1 / 2 / 3。
  - Confidence：确信度，50% / 80% / 100%（有实测数据或强证据支撑取 100%）。
  - Effort：人月投入，1-10（1 约半天，10 约 3 个月以上）。
  - Score = (Reach × Impact × Confidence) / Effort。

### 6.2 RICE 评分表

| 功能 | Reach | Impact | Confidence | Effort | Score | 优先级 | 说明 |
|------|-------|--------|------------|--------|-------|--------|------|
| 当天课程主界面（课程名 + 时间 + 地点三要素）| 10 | 3 | 100% | 4 | **7.5** | P0 | 产品核心，使用频次最高，直击"确认今天在哪上课" |
| 教务系统导入（SSO 登录 + 课表抓取 + 周次 / 单双周 / 多教师多教室解析）| 10 | 3 | 100% | 5 | **6.0** | P0 | 用户已实测可登录抓取；导入不成立则整个产品不成立 |
| 多学期课表管理（学期列表 + 切换 + 当天课程自动刷新）| 8 | 2 | 100% | 3 | **5.33** | P0 | 直击"换学期"关键场景；不刷新即失真 |

### 6.3 每个功能的验收要点（详细见第 8 节）

1. **当天课程主界面**：默认进入即为"今天"；每条课程卡至少显示课程名、上课时间、上课地点；无课时显示明确空状态（区分"今天没课"与"假期 / 学期未开始"）。
2. **教务系统导入**：输入学号 + SSO 密码后能拉到课程；解析需覆盖第 4.2 节四种形状。
3. **多学期课表管理**：可新增 / 命名 / 切换学期；切换后当天课程按新学期数据刷新，无旧数据残留。
4. **上课提醒**：可设置提前时长（默认课前 15 分钟）；通知内容含课程名 + 时间 + 地点；需应对国产 ROM 后台清理。
5. **手动编辑课程**：可新增 / 修改 / 删除单条课程实例（含周次规则），作为导入失败时的兜底。
6. **周视图 / 网格**：7 列（周一至周日）× 节次行；正确体现单双周与换教室；线上 / 不排座课程有独立入口而非硬塞网格。
7. **过渡动画**：页面切换、列表内容更新、学期切换均有顺滑过渡，无跳变、无卡顿。
8. **桌面小组件**：至少一种尺寸显示当天课程三要素；换学期或改课后能刷新。

## 7. 明确不做清单（Out-of-Scope）

> 每条给出**原因**与**何时再考虑**，避免"以后再说"式的模糊排除。

| 不做项 | 原因 | 何时再考虑 |
|--------|------|-----------|
| 上架应用商店 / 对外分发 | 自用项目，无分发需求；上架涉及签名、隐私政策、审核成本，投入产出比为零 | 若用户想分享给同学、或作为个人作品 / 简历项目时 |
| 产品级账号体系 / 登录注册 | 只有一个使用者，本地存储即可；竞品"强制手机号注册"正是差评来源 | 若变为多人使用，或需要跨设备识别身份时 |
| 云同步 / 后端服务器 | 无服务器是既定约束（节省成本、降复杂度）；单一设备无需同步 | 用户换手机想保留数据，或需要手机 + 平板多设备同步时 |
| 社交 / 分享（课表分享、找同课同学、班级群）| 竞品臃肿与差评的主因之一，自用零需求 | 若用户想帮室友 / 同学导入同一套课表时（届时以"分享码 / 导出文件"最小实现，不做社交）|
| 广告 / 付费 / 会员 / 皮肤商城 | 自用无需变现；且"无广告"是本产品第一卖点，永不引入 | **永不考虑**（产品定位即为零广告） |
| 空教室查询 | 依赖全校用户打卡数据，单人无法实现，与核心无关 | 基本不考虑（需多用户数据源才成立）|
| 成绩查询 / 考试倒计时 / 绩点 | 超出"看课表"范围，教务系统本身可查 | 若用户明确需要且愿意扩大范围时单独评估 |
| 校花校草 / 小纸条 / 下课聊 | 娱乐社交，与核心完全无关，是竞品被吐槽的重点 | **不考虑**（保持范围克制）|
| 拍照 / OCR 导入课表 | 教务直连已够用；OCR 识别错误风险高（竞品"识别错排课"差评即前车之鉴）| 仅当教务改版且无任何可解析途径时，用"手动编辑（P1）"兜底，仍不做 OCR |
| iOS / 跨平台 / 桌面端 | 用户是 Android，技术栈锁定 Kotlin + Jetpack Compose | 用户更换 iPhone 或需要 PC 端时 |
| 课程笔记 / 作业 / DDL / 待办管理 | 属"任务管理"范畴，超纲 | 不考虑（避免重蹈竞品臃肿覆辙）|
| 多语言 / 国际化 | 单一中文用户 | 不考虑 |

## 8. 关键用户故事（As a… I want… so that…）

1. **开学导入**：作为大一新生用户，我希望用学号 + 统一身份认证一键导入本学期课表，这样我不用一节课一节课手动录入。
2. **今日确认（核心）**：作为用户，我希望打开 App 第一眼就是今天要上的课的课程名、时间、地点，这样我出门前 3 秒就能确认今天去哪上课。
3. **单双周与换教室正确**：作为用户，我希望 App 正确区分"2-16 周双周""3-15 周单周"，并知道大学物理 B(1) 第 2 周在 E教305、第 3-16 周在 B105，这样我第 3 周不会跑错教室。
4. **实验课每周不同教室**：作为用户，我希望大学物理实验 B(1) 第 12 周显示"202 实验室1"、第 13 周显示"309 实验室11"，这样我每周都去对实验室。
5. **换学期**：作为用户，我希望学期结束时能一键切到新学期课表，且切换后"当天课程"自动刷新，这样我不用清空重来、也不会看到上学期的旧课。
6. **桌面小组件**：作为用户，我希望桌面小组件直接显示今天课程，这样我不用打开 App 就能看到今天上什么。
7. **上课提醒**：作为用户，我希望课前收到含课程名和教室的提醒，这样早八不会迟到、不会记错教室。
8. **周视图规划**：作为用户，我希望有一张整周网格，这样我能一眼看出"周四下午和周五空、周末没课"，安排回家或自习。
9. **线上 / 无固定地点课不遗漏**：作为用户，我希望尔雅通识课《航空与航天》和"军事技能"这类没有实体教室 / 无固定时间的课也能正确显示在"线上 / 不排座"分区，这样它们不会被网格吞掉或被错排。
10. **导入失败兜底（P1）**：作为用户，我希望在教务系统改版导致导入失败时，能手动补录或修改课程，这样 App 不至于当天彻底作废。
11. **顺滑动画**：作为用户，我希望页面切换和内容更新有顺滑的过渡动画，这样用起来是现代的、不是卡顿老旧的。
12. **无广告安心用**：作为用户，我希望 App 全程没有任何广告和摇一摇跳转，这样我看课表时不会手一抖被弹去别的应用。

## 9. 验收标准（Given / When / Then）

> 说明：本节为可执行验收用例，测试与开发以此为"规格即契约"。

### 9.1 导入与解析

- **Given** 用户已连接网络并输入正确的学号 + SSO 密码，**When** 触发导入（学期起始日 2026-09-14），**Then** 成功入库全部课程，且课程总数、每门课的周次范围、时间、教室、教师与教务系统一致。
- **Given** 已导入「大学物理B(1)」，**When** 查看该课在第 2 周与第 3 周的安排，**Then** 第 2 周地点为 `E教305`，第 3 周起地点为 `B105`。
- **Given** 已导入「自动化专业导论与职业生涯规划」，**When** 查看第 2 / 3-4 / 5 / 6-7 / 8 周的教师，**Then** 依次显示为 陈国初（D教203）/ 蒋璐峥（B203）/ 陈国初（B203）/ 于妍（B203）/ 陈国初（B203）。
- **Given** 已导入单双周课程，**When** 当前日期落在单周，**Then** 仅单周课程出现在"当天课程"与周视图；双周课程不出现（反之亦然）。
- **Given** 输入错误的 SSO 密码，**When** 触发导入，**Then** 明确提示"账号或密码错误"并允许重试，不产生半截错误数据。
- **Given** 导入过程中断网，**When** 导入进行中，**Then** 显示失败原因（网络错误）并提供重试；已入库数据不被破坏。

### 9.2 当天课程主界面

- **Given** 今天是学期内的上课日（如周一），**When** 打开 App，**Then** 默认展示当天课程列表，每条至少包含课程名、上课时间、上课地点三要素。
- **Given** 今天无课，**When** 打开 App，**Then** 显示"今天没有课"空状态，且与"假期 / 学期未开始"状态在文案上可区分。
- **Given** 当天某节课来自线上课程，**When** 查看当天课程，**Then** 该课显示为"线上"而非空白教室。

### 9.3 多学期管理（关键场景）

- **Given** 已存在"2026-2027 学年第 1 学期"课表，**When** 用户新增并切换到"2026-2027 学年第 2 学期"并完成导入，**Then** 当天课程主界面在 3 秒内刷新为新学期数据，且不出现任何上一学期的课程。
- **Given** 用户从学期 B 切回学期 A，**When** 切换完成，**Then** 当天课程、周视图均按学期 A 数据渲染。

### 9.4 上课提醒

- **Given** 已开启提醒且默认提前 15 分钟，**When** 距某课开始 15 分钟，**Then** 收到含课程名 + 时间 + 教室的通知。
- **Given** 手机处于后台清理激进的国产 ROM，**When** 应用不在前台，**Then** 提醒仍能准时送达（送达率见成功指标）。

### 9.5 手动编辑（P1 兜底）

- **Given** 自动导入失败，**When** 用户手动新增一门课（含周次规则），**Then** 该课出现在当天课程 / 周视图中，与导入课程并存不冲突。

### 9.6 周视图 / 网格

- **Given** 当前处于第 3 周（单周），**When** 打开周视图，**Then** 网格仅渲染命中单双周规则的课程，且换教室的课显示对应周的教室。
- **Given** 存在线上 / 无固定时间地点的课程，**When** 打开周视图，**Then** 这些课不硬塞进网格，而在"线上 / 不排座"分区可查。

### 9.7 过渡动画

- **Given** 用户在"今天""周视图""设置"之间切换，**When** 触发导航，**Then** 有顺滑过渡动画，无白屏跳变、无可感知卡顿。
- **Given** 学期切换或数据更新完成，**When** 内容变化，**Then** 列表以过渡动画呈现新旧更替，而非瞬时闪烁。

### 9.8 桌面小组件

- **Given** 用户把小组件添加到桌面，**When** 查看小组件，**Then** 显示当天课程三要素（或"今天没有课"）。
- **Given** 用户切换学期或手动改课，**When** 返回桌面，**Then** 小组件内容随数据更新。

## 10. 边界条件

| 类别 | 场景与处理 |
|------|-----------|
| 空状态 | 今天无课 / 假期中 / 学期未开始 / 尚未导入课表，四种状态文案须可区分；未导入时提供"去导入"引导 |

## 12. 数据埋点方案（自用项目本地化改造）

本产品无后端服务器，不做第三方埋点上报（符合"不采集隐私"）。改为**本地事件日志**，用于用户自检"哪个环节出问题"，仅存本机、不联网上传。

| 事件类别 | 事件 | 说明 |
|----------|------|------|
| 导入 | import_start / import_success / import_fail | 记录发起、成功课程数、失败原因（网络 / 鉴权 / 解析）|
| 导入准确性 | import_verify_diff | 关键：记录解析结果与预期的差异（如课程数、周次），供人工核对 |
| 激活 | first_view_today | 用户首次看到今日课程 |
| 使用 | today_view / week_view_open / widget_refresh | 各页面使用频次 |
| 切换学期 | term_switch + today_refresh_ok | 切换学期后当天课程是否正确刷新（核心）|
| 提醒 | remind_scheduled / remind_delivered / remind_missed | 提醒是否准点送达（对应"迟到"指标）|
| 兜底 | manual_course_added | 手动编辑被使用，意味着导入可能失效 |
| 异常 | error_occurred | 解析失败、崩溃、权限拒绝等 |

**事件命名规范**：`{对象}_{动作}`（如 `today_view`、`import_success`、`term_switch`）。
**属性规范**：每个事件附带 `timestamp`、`version`、`term_id`（不含任何个人身份信息）。
**不采集**：不上报 IP、不上报学号 / 密码、不存原始教务页面内容。
